# Задание 3

Проблемы текущей архитектуры при росте нагрузки:
1. Время ответа ins-product-aggregator может выполняться достаточно долго, так как ходит в сторонние сервисы
2. Во время запросов в сторонние сервисы могут возникать ошибки из-за могут не обновиться данные и ближайшее обновление прийдет в следующий цикл
3. Плохо масштабируется, так как при увеличении количества страховых копаний


Решение:
1. Поднять kafka для обмена событиями между разными сервисами
2. У kafka будет 2 топика: обновление данных пользователей, обноволение данных от страховых компаний
3. Что бы избежать рссогласованности данных, особенно для данных о пользователях, стоит использовать паттерн TransactionalOutbox
